# FDE 客户诊断（Codex Skill）

把客户访谈与真实流程材料转成三项可讨论、可验证的交付：**工作流诊断、首期试点范围、验收清单**。

这不是自动替客户选型或部署的工具。它先追溯实际工作怎样完成、哪里出错以及谁承担复核，再判断是改流程、用确定性规则，还是引入可验证的 AI 辅助。没有配对样本、基线或授权时，输出会明确停留在假设与验证计划，而不是承诺准确率、ROI 或全自动化。

## 适用场景

- 售前访谈后，需要把零散叙述还原成现状流程和问题证据。
- 想从多个候选环节中选一个边界清楚、能快速验证的首期试点。
- 要与客户提前约定样本、人工审核、异常出口、指标、验收证据和停止条件。

不适用于直接处理未经授权的客户资料、自动写入客户系统、代客户发布内容，或仅凭访谈断言某产品的现行价格与合规能力。

## 使用

将本目录作为 Codex skill 放在 `~/.codex/skills/fde-customer-diagnostic/`，然后调用：

> 使用 `$fde-customer-diagnostic`。以下是客户访谈纪要和几份样本的说明，请输出工作流诊断、首期试点范围和验收清单；把事实、假设与待确认事项分开。

可提供访谈纪要、流程截图或 SOP、样本输入、人工认可的结果、现有模板与规则。无需为首次讨论收集全量客户数据；请先脱敏并确认资料使用范围。技能默认用中文输出一页结论及必要附表，详细工作表见 [`references/diagnostic-worksheet.md`](references/diagnostic-worksheet.md)。

## 方法与边界

1. **看现状**：触发、输入、操作者、判断、交接、输出、审批、异常和返工。
2. **查根因**：用真实案例区别源数据问题、处理问题与审核问题，保留来源和不确定性。
3. **收窄试点**：优先一段有配对样本、权威对照结果和明确人工负责人的流程；不预设技术栈。
4. **约定验收**：先记录基线，再与客户确定阈值；逐项留差异、计时、异常和使用者确认的证据。

例如“图纸转清单”场景，可以先用同版本原始图纸和已审核人工清单做逐项对照，交付差异与无法判断项，而不是直接建设整套报价平台。这个例子用于说明诊断方法，不包含真实客户文件，也不表示技术路线已经验证。
