# 诊断工作表（按需裁剪）

这是一份输出结构，不要求客户在首次访谈时填满。每条关键内容标明证据定位和状态：事实、陈述、推断、假设或建议。

## 1. 一页结论

- **当前最值得验证的一段流程**：起点 → 终点；谁使用结果。
- **业务问题与可能根因**：实际症状、受影响者、根因假设及反证需求。
- **建议先做／暂不做**：各自的理由和待确认前提。
- **现在能否进入试点**：能／先补样本／先解决权限或数据边界。

## 2. 现状工作流

| 节点 | 触发与输入 | 操作者／系统 | 实际动作与判断 | 输出／交接 | 等待、异常与返工 | 来源与状态 |
|---|---|---|---|---|---|---|

补充：频次、单次耗时、峰值、错误案例、审批人与数据归属。数字未知时记录取得基线的方法，不估填。

把每个问题写成「症状 → 根因假设 → 需要查看的证据 → 可行纠正方式 → 如何验证」。先分别检查上游源数据、当前处理和下游审核，避免把上游错漏归咎于自动化工具。

## 3. 首期试点卡

| 项目 | 要写清楚的内容 |
|---|---|
| 工作流切口 | 一段起点和终点明确的流程；为什么先选它 |
| 输入与对照 | 原始输入、人工认可结果、版本配对方式；缺失样本如何补 |
| 纳入／排除 | 标准件、例外、非标、高风险决策分别如何处理 |
| 处理分工 | 确定性规则、AI 辅助判断、人工批准各做什么 |
| 输出与异常 | 结果格式、无法判断项、人工接管与返工路径 |
| 数据与权限 | 可用数据、脱敏、所在环境、访问和审批负责人 |
| 基线与成本 | 现状计时、错误／返工、试点投入；无证据先不估收益 |
| 停止条件 | 越权、错误外发、关键错误、成本失控等具体触发项 |
| 决策人 | 谁提供样本、谁试用、谁验收、谁决定下一阶段 |

若尚未确认源文件、权威结果或使用授权，把试点改成「样本核验／可行性验证」，不预先承诺系统交付。

## 4. 验收清单

| 检查项 | 样本与版本 | 测量方法及阈值 | 证据留存 | 责任人 | 未通过处置 |
|---|---|---|---|---|---|

至少检查：输入完整与版本对应、逐项结果差异、漏项／多项／错误类型、无法判断项的人工出口、端到端耗时与人工复核时间、权限与数据边界、失败恢复、真实使用者确认。阈值应在看过基线后与客户共同确定；不能把“演示成功”写成验收通过。

## 5. 下一次访谈只问关键缺口

- 最近一次真实任务从哪份输入开始，到谁收到哪份结果才结束？请指给我看。
- 最近三个月哪类错误或返工最常见？挑一例按发生、发现、补救顺序说。
- 哪份结果是团队认可的对照版本？与源文件如何配对？
- 哪些项你们一定要人工确认？出现无法判断项时由谁接手？
- 哪些资料可用于本地试验，哪些不能离开客户环境？谁能批准？
- 试点后谁会实际使用，谁有权决定继续或停止？

## 6. 图纸转清单的可选示例

若客户流程涉及 CAD 图纸转家具清单，可先核对同版本的原始图纸与已审核人工清单、所涉产品编码与规格子集、正式输出模板和统计规则。第一份结果可设为「图纸对象—清单行」逐项匹配及差异表，记录漏统、多算、规格不明和人工核对时间。图块命名、DXF 提取、视觉识别均是候选路径，不能在看过真实样本前写成已证实方案；报价、选型或设计源头错误需另立边界。示例不代表任何客户已授权使用其资料或已通过验收。
